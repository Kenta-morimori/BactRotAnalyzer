# ADR 0008: 中央対象の自動候補と保存動画による一括承認

- 状態: 採用。ADR 0005の「初期対象・記録境界後の対象は必ず人が指定し、撮影ごとに確認する」条件を置換する。

## 背景と決定

撮影ごとの対象クリック・ROI・確認チェックは撮影数に応じた負担になる。
利用者の「原則として画像中央のビーズが対象」という指定を、対象の真値ではなく候補作成の前提に用いる。

- 保存条件を優先し、未設定の閾値に2000を提示する。閾値の自動最適化は行わない。
- 既存の10倍線形拡大・連結領域から、領域重心が画像中心に最も近い一意な領域を選ぶ。開始点はその前景内とし、穴の中の重心を指定点にしない。候補なし・同距離候補・画像端接触は決定不能として扱う。
- ROI未設定時は既存の連続冒頭1秒以内・最大200フレームの推定を使い、撮影中は固定する。支持不足で全視野へ黙って置換しない。
- 記録境界後は独立した区間として中央候補を選び直す。元フレーム・時刻・欠測・明示再指定を保持し、区間間の対象同一性や角度をつながない。
- 同一の追跡結果から仮抽出CSVと横並びMP4を作る。全保存観測を収録し、動画の50 fpsを撮影時刻と混同しない。
- 候補と動画をローカル保存するが、解析入力へは利用者の一括承認時だけ反映する。承認可能な撮影をまとめて選び、決定不能・未完了・利用者が保留した撮影は明示的に除く。
- JSONへ承認対象No.と確認成果物を保存し、day指定だけの解析はこの対象を使う。承認情報のない旧JSONの解析対象は変えない。未承認No.の明示実行は拒否する。
- 条件・校正・元入力・実装・成果物が一致した測定だけを再利用する。不一致は再生成・再承認を要求する。背景変更は既存の背景再計算へ渡す。

## 代替・影響と限界

毎回の手動初期指定は候補取り違えを減らせるが、確認操作を撮影数だけ要求するため既定にしない。
無確認の全自動採用は、中央の別物体・結合像・区間間の対象変更を保証できないため採用しない。
保存した動画を利用者が確認し、違う撮影だけ指定・閾値・ROIを修正する。中央選択や方法間一致から物理的精度合格を主張しない。

保留分を黙って解析から落とさず、承認画面に解析対象と保留No.を示して保存する。
未完了成果物を承認せず、既存設定・旧動画を自動上書き・削除しない。確認用の試料別保存先は前処理成果物専用で、標準解析のフェーズ別出力契約は変えない。
確認動画・座標・詳細条件はローカル専用とする。CLIからの仮抽出にもclean Gitと実行履歴を適用する。

## 検証

合成画像で中央領域と明るい別物体、穴・複数候補・画像端、ROI支持不足、欠測・ギャップを確認する。
動画とCSVの同じ採用領域・重心、両パネルのROI、全観測と実時刻の対応を確認する。
一括承認・部分保留・再生成・再利用・改変拒否・設定競合・中断復帰・旧JSON互換性を検証し、実CLIのday指定解析で元の試料番号が維持されることを確かめる。
