# ADR 0006: 提供Mean CSVをTIFF元観測と従来の上昇点検出へ接続する

- 状態: 採用
- 置換する判断: ADR 0005の「上昇境界もユーザーが提供し、自動検出しない」という分担。

## 背景

背景輝度をユーザー側で解析する範囲は、画像からMean CSVを作成するまでである。
その後の上昇点検出と前後分割は従来の解析処理を使う。config.iniのないTIFF記録にも同じ接続が必要である。

## 決定

- config.ini任意の共通JSONを維持する。入力源はJSONのsourceとCLIのinput-sourceで明示し、一致を検査する。config.iniなしでも撮影時刻はTIFFタグから取得する。
- 同名のbrightness_data/<撮影名>.csvをJSONへ登録する。新規草案では存在する同名CSVを関連付け、既存JSONにはattach-brightnessで追加する。対象・番号・閾値・ROIは変更せず、異なる既存の背景設定も黙って置換しない。
- ImageJ形式は[inch],Mean列を持ち、保存TIFFと同数の行であることを要求する。従来読込と同じくMean行を保存スタックの順序に対応付ける。[inch]を時刻・原フレーム・物理校正として解釈しない。
- 各行に対応するTIFFの接尾辞+1と元時刻を付与する。記録gapや時刻欠測を保持し、欠落行を圧縮しない。CSV自体にはフレームIDがないため、同名・同数と保存順による対応という前提を結果へ記録する。独立した行同一性検証とは扱わない。
- 設定された解析範囲を選択した後、既存のdetect_rise_indexを同じパラメータで実行する。baseline-ratio、sigma-threshold、min-consecutiveをCLIから渡し、既定値0.5、3.0、3を維持する。検出器内部の計算と閾値・窓は変更しない。
- 検出行を元フレーム番号に変換し、前の揺らぎ・FFTと後の切替診断へ渡す。検出行の元時刻または輝度が欠測なら境界は未判定とする。検出用の内部補間値を保存Meanや元時刻へ書き戻さない。
- 明示的なrise_source_frameは自動検出より優先する。背景未提供、検出なし、検出行の必要観測欠測は理由付きで未実行・未判定を維持する。上昇点を刺激到達や物理的反転の確定結果とはしない。
- 自動/手動・採否・パラメータ・診断値をmanifestとsettingsへ記録し、rise_summaryにも検出方法・状態を付記する。背景の内容・検出条件が変わっても重心キャッシュを混用せず、同じ抽出設定は再利用する。
- 元画像からの背景輝度抽出、背景補正、重心・中心・角速度の手法や品質条件は変更しない。従来の元フレーム/時刻/欠測、符号、平滑化なし、V2主系列と停止測定の分離を維持する。

## 代替と影響・限界

手動境界だけを要求する方式は操作を増やし、Mean CSVの提供だけで従来の前後解析へ進めないため既定にしない。
新しい検出器や閾値最適化は入力接続の範囲を越えるため導入しない。
CSVの任意の横軸を時計へ読み替える方式やフレームレートからの時刻生成は採用しない。
同名・同数でもMeanの並びが誤っていれば検出できない。保存スタック順にCSVを出力することが必要である。
既存検出器は内部で欠測輝度を補間して変化候補を評価するが、実際の観測欠測は出力に残す。画像記録ギャップ中の刺激到達を確定する機能ではない。

## 検証

合成Mean CSVとTIFFで、保存順対応、異なる横軸の無視、原フレームgap・時刻欠測、範囲選択、行数不一致、検出器との一致、CLIパラメータ、手動優先、未検出、入力ハッシュ、重心再抽出の不要性を検証する。
一時Gitリポジトリの実CLIで、config.iniなしのTIFF・Mean入力から集約出力・前後境界・実行履歴まで確認する。
実測Meanの行対応や背景上昇点の妥当性は合成検証とは別に扱い、実測成果物を公開しない。
