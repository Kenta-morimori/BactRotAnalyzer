# ADR 0004: clean GitによるCLI実行とローカル実行履歴

状態: 採用

## 背景

解析時のブランチ・commit・設定・使用データが結果だけから判別できないと、
手法の比較と再実行を追跡できない。未コミットコードの結果をcommit済みの実装の結果として
扱うことを防ぎたい。実測データはGit管理せず、既存のフェーズ別出力契約は維持する。

## 決定

- `scripts/` の解析CLIは共有の `analysis_run` を通す。解析出力を作る前にGit状態を確認する。
  変更・ステージ済み変更・削除・未追跡ファイルがある場合、Git管理外、HEADなし、確認失敗は拒否する。
  dirty実行を許可するオプションは作らない。除外対象のデータと生成物は判定から除く。
- 実行のブランチ・完全なSHA・引数・環境・入力パスとSHA-256・時刻・終了状態を
  `outputs/_runs/<JST日付>/<時刻_秒以下_乱数>/manifest.json` に保存する。
  stdout/stderrと例外は隣の `run.log` に残す。例外とCtrl-Cも記録する。
- 入力descriptorからの再計算・再描画では参照先も識別する。
  相対参照は各既存ローダーの規則を保ち、JSONへのsymlink経由でも実際に読む表をhash化する。
  入力一覧は宣言した範囲の実行前候補であり、実際に読んだ全ファイルの監査記録とはしない。
- 入力列挙後と終了時にもGit状態とSHA・ブランチを確認し、変わっていればfailedにする。
  `SystemExit(0)` 等の正常終了要求も検査を迂回させず、検査成功後の要求自体はerrorにしない。
- 既存解析結果のパス・観測対応・科学的測定は変えない。実行履歴だけを別の場所へ追加する。
  ADR 0003の「解析結果に実行ID階層を作らない」判断は維持する。
- 開発テスト・help・下位関数呼び出しにはGitゲートを置かない。テストは一時Git作業ツリーと合成入力を使う。
  実測解析にはCLIを利用する。新規CLIも共有コンテキストへ接続する。

## 代替

- dirtyフラグだけを記録して許可する: 未コミットでの解析を防げないため採用しない。
- コード差分を実行ごとに保存する: 復元・秘密情報管理の負担を増やすため採用しない。
- 全結果を実行ID配下へ移す: 現行の参照・再描画契約を変更するため採用しない。
- OSレベルの全ファイル読み取り監査: 複雑さと移植性の問題があり、入力候補の明示とhash化を採用する。

## 影響と限界

解析前のcommitが必須になる。Gitの除外済みコードを実装に使うと追跡できないので使用しない。
ログは非公開の入力パスや診断値を含み得るため、データ同様にローカル専用とする。
ディレクトリsymlinkは参照先を辿り、実パスで重複・循環を防ぐ。
大きな入力のhash計算にはI/O時間を要する。候補一覧は未使用の入力を含む場合がある。
入力の同時更新を完全に防止するロックは行わない。終了前に戻されたコード変更も検出できない。
強制終了時はrunningが残る場合があり、complete以外を正常終了の証拠にしない。
Pythonのストリームを経由しないネイティブ/子プロセス出力は捕捉を保証しない。
依存版を記録するが、完全なlockと環境再構築の保証は別途整備する。

## 検証

一時Gitリポジトリで未ステージ・ステージ済み・削除・未追跡の拒否、Git確認失敗、
worktree・detached HEAD、同時刻の履歴分離、例外・Ctrl-Cの保存、実行中変更を検証する。
write・writelinesの捕捉と、正常終了要求でも未コミット変更・commit変更を拒否することを検証する。
descriptorへのsymlinkについて、再計算・再描画の既存の相対参照と入力hashが一致することを確認する。
合成結果表を実際の忌避応答CLIへ渡し、参照入力hashと結果・ログ・状態を検証する。
既存の科学計算回帰テストも継続し、計算手法・観測対応を変更していないことを確認する。
