# Issue #40: 条件付き重心軌道中心の解析接続

## 実装

`utils/functions/validated_rotation_center.py` は、中心に依存しない局所 x/y スペクトルから周期を推定し、5周期相当の中央窓を0.2秒ごとに評価する。窓幅は60フレーム以上・5秒以下とし、時間の欠落・逆行や重心欠測があれば棄却する。中心は #39 で選定した制約付き代数楕円と固定済み判定規則に合格した窓からだけ採用する。#40 では中心急変をまたぐ窓への対策として、窓前半と後半の中心差が観測半径の0.22倍を超えた窓を棄却し、この条件が隣接2窓以上続く箇所の周辺半窓幅も無効化する。合格中心は評価時刻の周囲0.2秒のフレームに割り当て、隣の無効窓や未評価の端へ持ち越さない。生の重心と時刻は詰めずに元のフレーム順で保持する。

`scripts/04_repellent_response_analysis.py` の既定 `--center-estimator validated` はこの経路を使う。従来の時系列中心方針は `--center-estimator legacy` で使用でき、`--post-rise-center-mode` はこの経路だけに適用する。ただし従来経路の**停止時に固定する中心**は、原点依存の非制約楕円で真円の中心がずれる再現例がCIで見つかったため、制約付き楕円で計算する。既存の `center_coordinate.csv`、`angle_time-series.csv`、`angular-velocity_time-series.csv` の列名と行対応は変えない。追加の `00_all_rotational_analysis/center_coordinate/center_assessment.csv` には試行ごとの窓・合否・理由を記録する。停止時刻が決まっている場合、その時刻をまたぐ窓は使わず、停止後の中心は欠測にする。無効中心の前後にある角速度区間は欠測となり、方向切替回数は欠測をまたいで符号をつながない。

## 再現検証

`python3 scripts/diagnostics/issue40_integration_check.py` は、既知中心の模擬軌道、`data/test_data` 10本、No.14 の設定済み解析範囲（原 AVI の2049–16384フレーム）を同じ経路で評価する。[全結果](tables/integration_summary.csv)にフレーム分母・採用数・窓数を保存した。No.14 は保存済み元重心を使用し、実データの真の中心誤差は計算しない。

| 入力 | 有効中心フレーム | 既知中心誤差 P95 |
| --- | ---: | ---: |
| 模擬・安定周回 | 920/1200 | 0.013 R |
| 模擬・方向反転 | 880/1200 | 0.012 R |
| 模擬・短い弧 | 0/1200 | — |
| 模擬・停止点群 | 0/1200 | — |
| `test_data` 10本 | 各920–1080/1200 | 真値なし |
| No.14 15.781–40秒 | 0/4836 | 真値なし |
| No.14 40–65秒 | 560/4991 | 真値なし |
| No.14 65–82.5秒 | 2101/3494 | 真値なし |
| No.14 82.5–87.579秒 | 219/1015 | 真値なし |

前半/後半の中心差0.22Rと周辺半窓幅の無効化は、中心が0.4R急変する探索例と線形移動例を見てから定めた**#40 追加規則**であり、#39 の事前判定規則へ遡って含めない。`python3 scripts/diagnostics/issue40_change_holdout.py` は未使用seed 4700–4729の各30試行を再評価し、[全試行表](tables/change_holdout.csv)に保存した。0.4R中心急変例では境界前後200フレームの有効中心は全試行で0、採用フレームの中心誤差P95の試行間P95は0.017R。安定周回・厚い楕円・反転・線形移動は、各試行で少なくとも920・920・840・920フレームを保持し、それぞれの中心誤差P95の試行間P95は0.015・0.075・0.016・0.030Rだった。これは単一の急変幅とノイズ分布に対する結果で、未知の変化点への保証ではない。

模擬データで方向反転をまたぐ中心は真の中心に近いが、生の角度差分には反転前後にも多くの細かな符号切替が残る。真の中心でも同じ問題が発生することを #39 で確認済み。したがって、この変更は**中心推定と無効区間の伝播**を実装するものであり、符号揺れの解消を主張しない。反転時刻の許容差が未定のため、平滑化は導入していない。

同じスクリプトは、No.14 の保存済み従来中心と新しい有効中心を元フレームで揃え、**両者が有効な同一の角速度区間だけ**を[比較表](tables/no14_angular_velocity_comparison.csv)に記録する。40–65秒では552区間で符号切替が新148回・旧158回、65–82.5秒では2093区間で新618回・旧626回だった。符号の不一致率はそれぞれ2.0%・1.7%。速度絶対値の中央値は新70.9/55.0 rad/s、旧70.4/53.9 rad/sと近い。15.781–40秒には共通の有効区間がなく、比較しない。これらは保存中心との差と生差分の挙動を示すだけで、動画から独立に確定した角速度や方向反転の正解率ではない。細かな符号揺れが依然多く残る点も明示する。

No.14 の82.5秒以降は、従来処理が窓不足で中心を保持した区間に重なる。今回の一部窓が判定を通っても、実際の回転または撮影・検出由来の周期変位かは確認できない。撮影系の周期揺れと重心軌道運動は重心座標だけでは区別できない。実データの有効割合は #39 の模擬分布で固定した判定閾値と窓配置に依存し、真値付きの正解率ではない。

## 互換性と確認範囲

テストでは、模擬1200フレームから既存の角速度解析とCSV保存まで実行し、中心CSVの `No.1_x` / `No.1_y`、角速度CSVの `No.1`、角速度行数1199、停止後・未評価端の欠測、判定表の追加列を確認した。全区間が不合格の試料も同じ角速度CSVに欠測のまま残り、判定行が0件でも判定CSVの見出しを出す。全56テストが通過した。`data/test_data` 10本のAVIは中心抽出から窓判定まで実行した。No.14 は保存済み重心を使った窓判定でも評価した。

追加の全入口スモーク検証では、`python3 scripts/04_repellent_response_analysis.py --day repellent-response/23 --output-suffix issue40-smoke --center-estimator validated` を実行した。day 23 の14試料の原AVI/TIFから時刻・背景・立ち上がり判定を通り、全時系列の中心・角度・角速度CSVが生成された。従来出力と比べ、中心CSVは18,432行×28列、角度CSVは18,432行×14列、角速度CSVは18,431行×14列で列名も一致。No.14 の設定済み解析範囲では中心2,880フレーム、角速度2,861区間が有効で、無効中心から有効角速度が作られた区間は0だった。

この実行で、立ち上がり前の揺らぎ解析が全欠測の角速度も処理し、欠測窓を前値で埋めたり大量警告を出したりする問題が見つかった。`fluctuation_analysis.get_sd_time_series` は欠測・データ数不足の窓を欠測として維持し、有限のデータ数だけを記録する。`run_pre_rise_fluctuation` は有効角速度が10点未満の試料を除外する。SDのFFTは欠測をつながず、最長の連続有効区間を使用する。全欠測の窓幅は標準化・FFT・特徴量を欠測のまま保存し、図示できる。

保存済みの14試料分の立ち上がり前時刻・角速度CSVを下流解析に再投入し、警告や例外なく完走した。元試料番号3、4、6、8、10、11、12、13の8試料が揺らぎ解析対象となり、No.14は全欠測のため除外された。出力の `sample_index_map.csv` は元試料番号を保持した。元No.12に対応する2.0秒SDは全欠測であり、FFTも空のまま出力された。No.3の0.1秒SDは有効2,981行、欠測15,452行（全試料を結合した18,433行）だった。この下流再投入は保存済みCSVを使い、全入口の原TIF/AVI処理は全時系列CSV生成まで確認した。
