# No.14：画像と重心軌跡を対応させた中心評価

`python3 scripts/diagnostics/issue38_no14_image_trajectory.py` で再実行する。入力は原 AVI、同名 TIFF、確定済み重心と現行中心の診断 CSV。前半・中間・後半からそれぞれ33枚の連続フレームを選び、静止図では8フレーム間隔の5枚を示す。全33枚を20倍遅く再生するGIFも保存した。各群は約0.160秒で、刺激前 FFT による周期約0.169秒に近い長さだが、実際に1回転したことを保証するものではない。

連続フレーム：[序盤](../figures/no14_image_trajectory_initial_invalid.gif)、[中心ずれ](../figures/no14_image_trajectory_early_displaced.gif)、[40秒をまたぐ窓](../figures/no14_image_trajectory_rise_crossing.gif)、[後半](../figures/no14_image_trajectory_later_reference.gif)、[端部保持](../figures/no14_image_trajectory_terminal_hold.gif)。各GIFは前半・中間・後半を横に並べ、原フレーム番号と時刻を表示する。

全5,074フレームを画像から再測定し、保存済み重心との差は最大 **2.1×10⁻¹⁴ px**。輪郭未検出、複数輪郭、画面端との接触はすべて0だった。表示する495フレーム（静止図75枚を含む）について AVI と同フレームの TIFF の画素値は完全一致。原TIFFログのDateTimeを読み直して保存時刻との一致を確認し、1始まりの原フレーム番号と時刻を記録した。[フレーム別測定表](../tables/no14_image_trajectory_frame_checks.csv)と[区間別要約](../tables/no14_image_trajectory_summary.csv)に検算値を残した。

40秒をまたぐ窓では面積が2,310.5–3,217.0 px²の範囲で変化し、画像でも後半に対象が大きくなる。一方、円形度の中央値は約0.892で、輪郭の分裂や欠けはない。面積変化は観測された事実だが、それだけで中心誤差の原因とは決められない。20–25秒にもフィットのずれがあるため、画像の大きさの変化だけでは全区間の異常を説明できない。

序盤と40秒前後のブロック別フィットは、全周を十分に覆わないものが含まれる。これらの中心差を実際のドリフトとは判定しない。二値画像には対象の向きを識別する模様がなく、回転中心の真値もないため、移動と回転の独立な目視判定はできない。代替手法は、観測した重心に対する原点依存性、保留時間ブロックへの残差、中心の再現性で比較する。

判定ラベルは5区間の探索的整理である。長半軸>2R・軸比>3・ブロック除外移動>0.25Rの組合せをフィット異常の目印に使い、後半は全ブロック被覆≥270°・除外移動≤0.1Rを再現性の目印にした。これらを本解析の採用閾値にはしない。

[代替手法と補完の比較](no14_center_alternatives.md)では原点感度、保留残差、既知中心の模擬試験を追加した。補完の許容誤差・採用閾値は設定していない。
