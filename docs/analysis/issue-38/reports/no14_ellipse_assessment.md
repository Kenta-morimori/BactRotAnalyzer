# No.14：楕円中心推定の実データ評価と #39 への引き継ぎ

## 結論

回転軸の傾きを前提として**楕円を基本モデル**にする。現行の非拘束代数法、楕円制約付き代数法、頑健な幾何学的楕円法を同じ確定済み重心・同じ134窓で比較した。円は参考比較として残し、円の残差が小さいことから物理的な円軌道を主張しない。

**制約付き代数法と幾何学的楕円法を両方 #39 に渡す。** 後半では幾何学的方法の中心が原点・初期中心・探索範囲の変更に対して再現され、保留残差も小さくなった。制約付き代数法は広い区間で中心の再推定幅が小さいが、厚い点群を小さな楕円として囲む場合があり、停止点群にも安定した中心が出る。計算の安定性だけで物理的な中心を採用しない。

独立した真の中心はない。全時刻の中心や、停止・反転・ドリフトを確定したものではなく、支持できる条件と未解決点を記録する分析の完了を #38 のmerge条件とする。

## 計算状態と妥当性を分ける

共通APIは `utils.functions.rotation_center_candidates.estimate_center(points, method, ...)`。データ名、AVI、窓の選び方に依存しない。`points`は `(n, 2)` の配列で、座標単位を維持する。欠測行はそのフィット内だけで除外し、入力配列を書き換えない。呼び出し側は元のフレーム番号・時刻を保持する。

```python
from utils.functions.rotation_center_candidates import estimate_center

result = estimate_center(xy_um, "ellipse_constrained")
other = estimate_center(
    xy_um, "geometric_ellipse", initial_center="median", bounds_scale=2.0
)
# result.center, result.axes, result.angle_rad
# result.status, result.converged, result.boundary_reached
# result.n_input, result.n_used, result.reason
```

| 状態 | 意味 |
| --- | --- |
| `computed` | 計算上の楕円が得られた。物理的中心の妥当性は未判定。 |
| `nonellipse` | 現行の二次曲線に実楕円の半軸がない。数値上の中心は別に残す。 |
| `not_converged` | 非線形最適化が規定の反復数内に収束していない。 |
| `boundary` | 収束したが探索境界に到達した。 |
| `insufficient_points` / `degenerate` / `failed` | 点数不足、二次元の広がり・計算階数不足、または計算例外。 |

`converged`と`boundary_reached`は独立に記録する。非線形最適化を行わない代数法の`converged`は未適用（None）。比較表の`ellipse_returned`は形状が返ったかを示す。`block_cv_valid`も形状が返った回数であり、計算上の問題がなかった回数は`block_cv_computationally_ok`に記録する。境界・未収束の試行も数値を保存し、隠して集計から除かない。`scientific_assessment`列は自動採用しないことを示す`not_assessed`であり、科学的な判断は下記の根拠付き評価に残す。

有限点30個という計算上の最小点数、0.2Rの損失尺度、探索範囲、収束許容値は比較の計算設定である。科学的な採用閾値、停止判定、補完条件ではない。

## 実データでの比較

時間順の4ブロックのうち1つを保留し、残り3つで再推定する。保留残差は保留点から楕円までの距離P95/R、中心変化は全点中心からの最大移動/R。下表は窓間中央値で、計算上の問題がある試行の数値も含む。

| 窓開始 | 手法 | 保留残差 P95/R | 中心変化/R |
| --- | --- | ---: | ---: |
| 20–35秒 | 現行 | 0.587 | 0.367 |
| 20–35秒 | 制約付き代数 | 0.762 | 0.074 |
| 20–35秒 | 幾何学的楕円 | 0.712 | 0.242 |
| 35–40秒 | 現行 | 0.576 | 0.219 |
| 35–40秒 | 制約付き代数 | 0.745 | 0.063 |
| 35–40秒 | 幾何学的楕円 | 0.698 | 0.211 |
| 65–82.5秒 | 現行 | 0.511 | 0.031 |
| 65–82.5秒 | 制約付き代数 | 0.552 | 0.031 |
| 65–82.5秒 | 幾何学的楕円 | 0.472 | 0.036 |

後半の幾何学的楕円は、現行と同程度の中心再現性を保ちながら保留残差を約7.6%減らした。一方、制約付き代数法は中心が安定していても残差が改善しない。序盤には残差の小さい長楕円と再現性の低い中心があり、残差だけで優劣を決められない。

### 感度と失敗理由

幾何学的方法の初期中心を「制約付き楕円の中心」「点群中央値」の2通り、探索範囲を既存・2倍の2通りで比較した。既存は中心が中央値±R、半軸0.1–3R。拡大は中心±2R、半軸0.1–6Rとし、正の半軸下限と角度範囲は維持した。

| 初期中心 | 範囲 | 計算成立 | 境界到達 | 未収束 | 基準中心との差 P95/R |
| --- | --- | ---: | ---: | ---: | ---: |
| 楕円中心 | 既存 | 118 | 15 | 1 | 0（基準） |
| 楕円中心 | 2倍 | 124 | 9 | 1 | 0.760 |
| 点群中央値 | 既存 | 119 | 14 | 1 | 0.026 |
| 点群中央値 | 2倍 | 126 | 7 | 1 | 0.755 |

各条件134窓、反復上限80。未収束1窓（約60.85秒開始）は各条件で上限320にすると収束し、感度表に追加した。基本4条件536件と追加4件の計540件。未収束を即座に軌道情報不足とは判定しない。

65秒以降の拡大範囲による中心差P95は約3.0×10⁻⁵R。一方、序盤・一部40秒前後では拡大で中心が大きく変わり、17.78秒開始窓では中央値初期値・拡大範囲で基準との差が2.16Rだった。範囲を拡げて収束しても妥当な中心になったとは言えない。大きな差はモデルの非一意性、局所解、窓内の軌道変化などの候補を残す。

現行法の原点感度P95は35–40秒で1.985R。代替法の原点感度は小さいが、それだけで短い弧・停止点群の物理的中心は支持できない。模擬試験でも短い弧・停止点群の中心誤差は約1主半径だった。No.14の二値画像から独立な反転時刻・回転数は確定できず、目視真値を作らない。

## merge条件の確認と引き継ぎ

**追補:** 元画像・観測点群サイズ・4窓幅の比較を追加した。[最新のmerge条件と引き継ぎ](no14_window_width_assessment.md)を参照。現行幅は比較基準で、最適幅の認定ではない。

#38は分析の完了でmergeを判断し、候補の最終採用や全区間の中心確定を必須にしない。

- 入力対応：同じ原フレーム・時刻・重心で全134窓を比較し、原フレーム両端と点数を表へ保存。
- 実データの証拠：3楕円法の比較表、代表5区間の対応図、初期値・範囲・反復回数の感度表を保存。
- 再利用性：候補APIはデータ名に依存せず、#39のテスト動画から抽出した重心へ同じ関数を呼べる。
- 計算確認：既知中心の楕円、平行移動、短い弧、停止点群、欠測、非楕円、未収束についてテスト。原点感度は現行法の既知の問題として残す。
- 品質確認：既存テストとCIの結果をPRに記録する。画像・数値の支持状況とCIの通過は別の条件として扱う。
- 本解析：候補APIを本解析から呼ばず、既定中心・角速度・反転判定・補完を変更しない。CI整備のため既存コードの書式・型の整合性も修正した。

#39では、制約付き代数法と幾何学的方法を複数候補としてテスト動画で検証する。既存窓に加え、停止・反転・軸比の大きな楕円・実際の中心移動の条件を確認する。初期値・探索境界・反復上限の感度も同時に評価する。

最終採用規則、中心の無効判定、補完条件は未決定。今回の補完は円の推定中心列の参考比較として残し、楕円中心の支持や補完条件の根拠へ流用しない。#39の「比較前に許容範囲を設定する」という条件は、今回の結果とは分けて検討する。今回の結果に合わせて物理的な許容値を後付けしない。
